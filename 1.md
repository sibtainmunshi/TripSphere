# Project Vision

## Tagline

**From "Where should we go?" to "Remember that trip?" — Everything in One Collaborative Workspace.**

---

## Vision Statement

TripSphere is not a booking platform.

TripSphere is not just an expense tracker.

TripSphere is not another travel planner.

TripSphere is a **collaborative travel workspace** that manages an entire journey from planning the trip until preserving memories after the trip.

Instead of opening multiple applications such as:

* WhatsApp
* Google Maps
* Splitwise
* Google Drive
* Gallery
* Weather
* Notes

everything should exist inside a single premium workspace.

---

# Core Philosophy

The product should answer one question:

> **"What if every trip had its own digital workspace?"**

Every trip deserves its own place where:

* friends collaborate
* expenses stay organized
* bookings stay together
* photos stay together
* memories stay together

The workspace becomes the digital home of that journey.

---

# Product Identity

TripSphere should feel like:

* Notion for Travel
* Airbnb level polish
* Apple level simplicity
* Linear level smoothness

TripSphere should NEVER feel like:

* Student Dashboard
* Bootstrap CRUD Project
* Admin Panel
* Management System

---

# Product Goal

Create a platform that people actually want to use for planning trips.

The Python syllabus should naturally be covered through implementation rather than forcing academic features into the product.

Sequence:

↓

↓

Smooth Transition

Login / Signup

# Authentication

The authentication experience should be clean and modern.

Features:

* Login
* Signup
* Continue with Google (Future Ready)
* Forgot Password

Authentication should never feel like a default Django page.

---

# Home Screen

After login, users land on Home.

Home contains:

Recent Trips

Upcoming Trips

Archived Trips

Create New Trip

Recent Activity

Everything should use large premium cards.

Avoid tables.

---

# Planning a Trip

Users can start a trip in two ways.

## Option 1

Plan with AI

The AI assistant asks:

Destination Preferences

Budget

Number of Travelers

Trip Duration

Travel Style

The AI suggests:

* Destinations
* Estimated Budget
* Best Time
* Packing Suggestions

The user can immediately create a workspace.

---

## Option 2

Manual Planning

The user already knows the destination.

Simply enter:

Trip Name

Destination

Dates

Members

Create Workspace

This workflow should be equally important.

AI should never be mandatory.

---

# Trip Workspace

This is the heart of TripSphere.

Everything revolves around this workspace.

Users should feel that they have entered the headquarters of their trip.

The workspace should never resemble a dashboard.

It should feel like opening a premium digital travel board.

---

# Workspace Hero Section

Each trip gets its own hero section.

Example

GOA

21 Jul → 25 Jul

4 Travelers

Planning

31°C Sunny

Background:

Destination-specific hero image.

Examples:

Goa

→ Beach

Manali

→ Mountains

Dubai

→ Skyline

Every workspace feels unique.

---

# Trip Status

Every trip automatically changes state.

Planning

↓

In Progress

↓

Completed

No manual switching required.

This helps users instantly understand the current phase of their journey.

---

# Workspace Navigation

The workspace is module based.

Not page based.

Users interact with modules rather than navigating complicated menus.

Modules will be discussed in later sections.

---

# Quick Actions

Every workspace contains a quick action area.

Examples:

* Add Expense

* Upload Photo

* Add Booking

* Invite Member

Quick actions reduce navigation time.

---

# Members

The workspace always shows trip members.

Display:

* Avatar
* Name
* Role
* Online Status

Minimal and clean.

---

# Weather Widget

The hero section always displays current weather.

Weather should update automatically.

Future weather alerts can be added later.

---

# Design Language

The workspace should follow these principles:

* Large whitespace
* Premium typography
* Smooth transitions
* Rounded corners
* Subtle shadows
* Glass effects only where appropriate

Never over-design.

---

# UI Inspiration

The design language should take inspiration from:

* Airbnb
* Notion
* Linear
* Apple
* Arc Browser

The purpose is inspiration only.

Never copy layouts directly.

---

# Animation Philosophy

Animations should communicate state changes.

Use:

* Fade
* Slide
* Scale
* Stagger

Avoid:

* Bounce
* Cartoon effects
* Excessive motion

Animations should make the interface feel alive without becoming distracting.

---

# Development Rule

Every screen follows the same workflow.

Step 1

Build UI only.

↓

Step 2

Review UI.

↓

Step 3

User Approval.

↓

Step 4

Backend Integration.

↓

Step 5

Testing.

↓

Next Milestone.

Backend development must never begin before the UI has been approved.

---

# Claude Code Instructions (Global)

This project must be treated as a premium startup product.

Do NOT:

* Generate generic dashboards
* Use Bootstrap-looking layouts
* Rush backend development
* Skip animations
* Sacrifice UI quality

Always:

* Build polished UI first
* Wait for approval
* Connect backend after approval
* Keep components reusable
* Write clean, scalable code

Quality always takes priority over speed.
